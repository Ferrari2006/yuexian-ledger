# 赛题一 · 运营执行材料与记录模板

配合[平台运营方案](赛题一-运营方案.md)使用。以下包括本地内容草稿和待填写、待执行的记录模板，尚未发起外部联系、招募或平台发布。先确认官方统一实测日程与规则，正式结果按官方口径记录。

## 一、启动确认与渠道盘点

| 项目 | 当前状态或填写内容 |
|---|---|
| 官方实测起止日、数据截点、评分与归因说明 | 待官方信息确认 |
| 发布、浏览、交流、收费及公开范围 | 待走通平台后填写 |
| 主责与内容协助 | 待团队确认姓名、可用时间 |
| 主渠道、补充渠道与选择理由 | 资源尚不清楚，盘点后确定 |
| 参与范围、角色、工作目标与预算 | 准备阶段确认，不预填结果 |
| 示范、模板、邀请说明和活动入口 | 准备后填写实际链接 |

渠道逐一记录：内部编号、类别、组织者、预计覆盖的目标人群、合作意愿、允许发布的内容、入口、实际日期、归因能力和维护工时。未确认合作时写“待确认”，群成员数不直接写成实际触达。

首轮优先盘点一个目标用户匹配的图文账号或发布入口、一个获准交流的数据学习社群；课程教师或助教、竞赛队、社团和参与者分享作为可选资源。记录账号受众、维护投入、群内规则及进入平台的实际路径；不默认已有粉丝或合作社群。根据真实可用条件选主辅渠道，未选中的入口保留原因。联系方式和可识别个人记录保留在团队内部，公开仓库只放汇总与脱敏证据。

## 二、准备性需求交流提纲

建议先与3—5位潜在用户及至少1位可能的组织者交流，人数为工作建议，不代表已经完成或具有代表性。

向潜在用户询问：

1. 最近有没有做过一份数据项目？现在放在哪里、给谁看？
2. 上一次需要展示、求反馈或找参考案例时，具体怎么做？哪里费力？
3. 如果整理已有项目，你最担心时间、公开范围、署名还是其他问题？
4. 看过示范和模板后，你愿意做哪一个动作？为什么？
5. 第一次用完后，什么具体变化可能让你再次打开？

向组织者补问：活动是否适合成员当前任务、允许怎样通知、需要投入多少时间、怎样组织反馈、有什么必须满足的条件。记录实际使用经历，区分用户表达、团队解释和待验证判断，不把口头兴趣当作实际采用。

## 三、作品发布模板

按以下顺序整理一份已有项目：

- **标题与一句话价值：** 这份作品解决什么问题，适合谁看？
- **问题与场景：** 任务是什么，为什么值得分析？
- **数据与来源：** 来源链接、样本范围、使用条件；合成或示例数据明确标注。
- **方法与过程：** 关键步骤、工具和必要假设。
- **主要结果：** 一张关键图与简短解释，避免只贴运行输出。
- **限制与适用范围：** 哪些结论不能据此推出？
- **材料入口：** 能打开的作品、代码或附件链接，说明复现或使用步骤。
- **作者贡献与交流问题：** 团队成员分工，希望获得哪方面反馈？

复核时检查内容、图表、链接、来源和署名。材料尚未获准公开时先脱敏或不纳入展示。示范作品与用户作品分开标记。

## 四、邀请与反馈说明草稿

### 4.1 给组织者的合作说明

拟组织一次“数据作品交流”活动，邀请已有课程或竞赛项目的同学，将成果整理成容易理解的作品，并交换具体反馈。团队准备示范、模板、答疑和汇总，希望与您确认成员需求、可用入口、公开范围及活动时间。首次先做小范围体验，再根据真实参与和组织成本决定是否继续。

### 4.2 给参与者的活动说明

如果你已经完成过一份数据项目，可以用发布模板把问题、方法和结果整理清楚，并提出一个希望讨论的问题。也可以先查看示范，围绕图表、方法或结论给出具体反馈。活动提供集中答疑与反馈安排，公开哪些材料由作者确认。

发送前必须补齐：实际平台入口、活动时间、组织者、参与步骤、已确认的收费与访问条件、答疑和反馈时间。未确认的功能或效果不写入邀请。以上草稿尚未发送。

### 4.3 有效反馈格式

“我看了作品中的____。我理解你的目标是____。这里的____让我不清楚／值得进一步核对，建议____，理由是____。”

作者更新时说明采用了什么建议、改了哪里、还有哪些限制。复用记录补充来源链接、具体使用内容、适用任务和结果链接；不以泛泛致谢代替实际使用证据。

### 4.4 图文制作与复用清单

围绕同一示范准备项目整理前后对比、发布模板、反馈修改案例三类图文。每份素材记录标题、目标用户、一个核心信息、关键图或截图、完整示例链接和一个下一步动作。修改案例经作者确认，有真实记录才制作。

保留一份可编辑母版和完整说明；每次发布记录渠道、适配版本、实际入口、日期、数据截点及来源能否识别。所选社媒的访问与分享方式先核实，不预填可用外链或追踪功能。首轮不安排视频，后续若录屏能减少反复答疑再评估投入。

### 4.5 FAQ与集中答疑安排

FAQ至少覆盖活动适用对象、平台访问与注册、作品整理、材料公开范围、反馈方式和时间。答案只写已确认信息，记录问题来源与更新时间。主责在每轮活动前确定集中答疑时段和可处理范围。

同伴反馈按模板组织，团队为未获回应的作品安排补充。重复问题先更新FAQ，不能批量解决的具体问题在集中时段处理；积压时减少招募。记录答疑与反馈耗时，避免将团队时间默认为无限可用。

### 4.6 首次价值交付与确认记录

统一标准：用户第一次在DataClawHub中，通过我们提供的内容或服务，获得与当前需求相符、有记录支持的具体收益。初期以团队供给为主，后续用户互助按同样标准纳入并记录提供者。

| 记录字段 | 填写要求 |
|---|---|
| 任务与承诺 | 用户具体想解决什么，内容或服务事先承诺提供什么收益 |
| 材料或服务 | 模板、案例或反馈编号，DataClawHub入口，提供者及交付时间 |
| 达成标准 | 复用事先固定的承诺标准，用户结果出现后不降低标准 |
| 首次操作 | 获取相关材料、发布、具体提问等实际行为及时间，保留证据 |
| 具体收益 | 找到适用模板、形成提纲、解决疑问或得到可用建议等，对应简短说明或成果 |
| 状态与时间 | 已确认达成、已确认未达成、待确认、证据不足；分别记收益发生与确认时间，时间不明则注明 |
| 证据与观察 | 记录来源、材料或作品链接、队列和观察截止日；站外体验另记 |
| 分组与版本 | 首个承诺类型V1—V4在交付前确定，后续其他收益另记；每次更新保留日期与数据版本 |

确认提问可用：“你原本想解决什么？这份材料或建议是否帮助了你，具体体现在哪里？如果还没有用上或仍未解决，也请说明。”回答可简短，不要求逐人长访谈；泛泛称赞不足以确认收益。

同类材料复用一套承诺标准。例如承诺找到适用模板，确认适用即可；承诺帮助整理项目，则需提纲或实际应用记录。下载、交付或发布不自动说明价值达成，先获得模板价值也不必等待发布作品后才记录。

记录实际询问人数、明确回答人数和未确认状态，避免只挑满意用户确认。正式漏斗中收益发生时间按预设窗口判断，确认时间另存；收益时间或证据不清时列证据不足，不倒填为窗口内达成。

V1为找到适用模板，V2为整理项目结构，V3为解决分析疑问，V4为获得改进建议。各类型分别看操作、确认、达成、后续使用和投入；不因为某一标准更容易达成就认定该供给更好。

报告时同时给出已达成÷操作人数、明确确认÷操作人数、已达成÷明确确认人数，另列实际询问与未确认状态。例如10人操作、4人明确达成、2人明确未达成、4人未确认，三项分别为40%、60%和约66.7%，仅为演算。

## 五、传播与活动台账

每次主要通知或内容活动记一行，正式实测前准备空表，按实填写：

| 字段 | 填写规则 |
|---|---|
| 活动编号、阶段、日期 | 区分准备期、正式实测及收尾 |
| 渠道编号、内容版本、入口 | 留可复核链接或经许可的脱敏截图 |
| 图文母版与适配版本 | 共享素材制作记一次，每次适配与发布另记实际工时 |
| 目标人群、角色、希望的动作 | 写明本次是招募、首发、交流还是回访 |
| 发布与反馈安排 | 记录负责人、答疑时段、预计回应时间 |
| 实际参与与问题 | 按主方案定义记人数、次数和缺失项 |
| 投入、调整与下一步 | 分首次制作、适配分发、答疑反馈记录工时，另记现金、调整日期及原因 |

参与记录最小字段：内部匿名编号、是否团队或测试用户、新老用户、来源及来源依据、首次角色、注册时间、首次有效操作及证据、对应承诺与首次价值记录编号、后续有效操作及证据、是否活动要求或提醒后操作、观察截止日与成熟状态。需要识别同一人时内部保留映射，公开材料不附个人联系方式。

内容与反馈记录最小字段：作品编号、作者编号、角色、来源和公开确认、是否合格、发布与更新时间、进入活动时间、承诺回应截止时间、首次有效反馈时间、反馈内容、提供者、复用来源与结果、响应时长和是否逾期。小组作品注明实际发布者，其他成员不自动计为激活用户。

数据快照最小字段：起止日期、官方或团队口径、数据源、渠道、去重规则、分子、分母、缺失原因、观察窗口是否完整、记录人。仅有PV时保留PV标签，不填写UV；分母为零记“不适用”。

### 5.1 取数确认卡与用户行为记录

对注册、到达、首次操作、价值、后续使用和工时分别填写一张确认卡：实际来源、能取得的字段、可识别用户的依据、记录或导出方式、负责人、更新时点、缺失时的处理、是否已用测试记录核对。初始状态均为“待核实”，不要把计划来源写成已经取得的数据。

确认卡由运营主责维护，内容协助复核证据与重复记录。平台无法提供个人标识或行为时间时，不自行宣称接通全链路；保留可验证记录，无法算的转化或留存暂不可测。

一条用户行为按下表记录；同一用户的重复行为增加新行，不能覆盖首次发生时间：

| 用户匿名编号 | 行为与发生时间 | 材料或服务编号 | 首个承诺类型 | 证据来源 | 录入人与记录时间 |
|---|---|---|---|---|---|
| 待填写 | 待填写 | 待填写 | 待填写 | 待填写 | 待填写 |

素材、用户与行为使用稳定内部编号；个人映射留在内部。平台操作记录与人工确认分别注明来源，内容级阅读数据不强行匹配到具体用户。

|---|---|---|---|---|---|
| 待填批次／V1 | 待填 | 待填 | 待填 | 待填 | 待填 |
| 待填批次／V2 | 待填 | 待填 | 待填 | 待填 | 待填 |

表外同时列出未确定首个类型人数、实际询问人数、明确未达成、待确认、证据不足、未成熟用户、价值达成耗时及未完成数。类型未确定者仍留在整体队列，汇总不能漏掉。

后段操作分别标记活动要求、个别提醒后、自发或动机未知；不要仅因没有提醒记录就认定自发。各组投入记首次制作、适配分发及服务工时，共享投入按事前规则分配，保留未分配部分并核对总工时。

社媒内容快照单列阅读、收藏、评论与分享，不直接合并为平台激活。平台访问、新注册、首次操作、首次价值和后续使用保留独立来源与证据。按主方案的结果、过程、诊断三层报告；成本以对应队列投入及持续有效用户平均工时为主，操作激活平均工时可作辅助。阶段平均工时不写成边际成本，来源无法匹配时不强行分配渠道成果。

以上为记录规范，尚无实际台账数据。工具可采用团队现有方式，但对外只提交脱敏汇总与必要证据。

## 六、阶段复盘模板

按一次完整运营循环填写：

1. **目标与条件：** 本轮服务谁、做什么、目标和统计窗口是什么？
2. **执行：** 发布了哪些图文，在哪些入口，复用了什么；首次制作、适配分发和用户服务各投入多少时间？
3. **结果：** 持续有效使用人数、完整链路达成率、平均工时；各阶段操作、价值达成及留存的分子分母，另列确认覆盖和未成熟队列。
4. **差距与证据：** 哪一步存在问题？数据与用户反馈各支持什么？
5. **调整：** 下一轮优先改内容、访问路径、FAQ或反馈安排中的哪一项，为什么，何时实施？
6. **边界：** 是否有归因缺失、观察期不足、课程任务或其他干扰？
7. **决定：** 继续、缩小、调整或扩大，分别需要什么条件？

正式实测结束后，以官方数据为正式结果依据，团队台账解释过程与限制。没有执行的项目保留为未完成，不补造人数、反馈、合作或增长成效。

## 七、首轮最小交付包

### 7.1 核心供给：项目表达模板与本地示范

可先复用第三节作品发布模板，首轮承诺V2：“帮助已有项目者整理出一份能讲清楚问题、方法和结果的项目提纲”。用户用自己的项目填出提纲或给出具体应用说明，作为达成证据；只收到模板不自动算达成。

以下示范取自本仓库“先别申报”原型，仅展示项目表达，不代表真实货运业务或平台用户成效：

- **问题：** 同一票货的不同单证可能出现字段差异，需要在申报前检查。
- **数据：** 使用仓库[合成样例](../data/shipments.json)。SH-2026-014的装箱毛重为12,480公斤，提单毛重为12,000公斤。
- **方法：** 计算相对提单的绝对差异，480÷12,000＝4%，与项目设定的3%演示阈值比较。
- **结果：** 该票触发重量检查阻塞；演示可展示证据并按人工选择的依据复检。
- **限制：** 3%是本项目演示规则，不是完整海关合规标准；合成样例表现不证明真实单据准确率。
- **材料：** 本地[演示页面](../demo/index.html)与源样例，公开平台入口需发布后另填。

对照表达：“我做了一个检查工具”可补充为“针对同票单证字段不一致，使用合成样例与确定性规则做申报前检查，并展示差异依据及复检过程”。这是本地项目讲解示例，用户可将同一结构应用于自己的数据项目。

### 7.2 首发图文文案与配图说明

**标题：数据项目做完了，怎样让别人看懂你的成果？**

你可能已经有代码、图表或课程报告。想把它整理成一份便于交流的作品，可以先回答四个问题：解决什么问题、用了什么数据、怎样分析、得到什么结果。再补上限制和材料入口。

这次“数据作品交流计划”提供项目整理模板与一份示范，帮助你先形成自己的项目提纲。你可以从一个已有项目开始，不必重新做一套分析。整理后提出一个具体问题，方便别人给出有内容的反馈。

**下一步：打开活动入口，查看模板，并用自己的项目填写提纲。**

配图拟采用两栏：左栏是只有文件和图表的简单说明，右栏是“问题—数据—方法—结果—限制—入口”的项目卡片。优先使用团队自有材料，实际图文仍待排版与核对。

发送前填入已验证的平台入口、时间和反馈安排；确认收费与访问条件。不提前承诺未落实的同伴反馈，不将此文案标记为已发布。用户可直接进入平台，加入社群不是必要条件。

### 7.3 首发与流程核验卡

| 核验项 | 实际填写或验证内容 | 当前状态 |
|---|---|---|
| 核心材料 | 模板、示范及首轮V2承诺 | 本地草稿已准备，平台发布待落实 |
| 首发入口 | 选定账号或渠道、组织者或负责人、允许的访问方式 | 待确认 |
| 实际日期与服务 | 官方实测窗口、首发时间、答疑时段、回应截止时点和可用工时 | 待确认 |
| 正式目标与取数 | 参与规模、角色、目标、来源字段、记录人 | 待确认 |
| 完整路径 | 从图文预览到平台入口、获取模板、形成提纲、确认收益，再到记录汇总 | 待实际走通 |
| 复核证据 | 测试编号、核验时间、问题、修复与再次核验结果 | 待填写；测试不计正式成效 |

如果入口失效、交付不可用或无法履行反馈安排，先修复再扩大招募；若只是某个分析字段拿不到，则明确不可测范围并调整记录方案，不编造数据。

### 7.4 每轮结束的行动选择

先检查逾期反馈、核心路径和服务工时，再看转化结果。积压时减少招募；确认覆盖低时补记录；确认充分但未达成多时改内容或承诺；价值成立但后段使用少时试验一次有实际价值的更新。只有窗口可比、服务能承接、投入可承担时，才小幅扩大一类内容或一个入口。

记录决定、依据、负责人、执行日期和下一次核对时间。暂未确定目标或时限时写待确认，不把规则本身当成已经完成执行。
