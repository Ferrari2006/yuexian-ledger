# 文本单证接入与证据记录

日期：2026-10-14。基于主分支 `1198f6f`。新增可读取本地输入的文本单证包入口，原有合成演示、规则、运营材料继续使用现有工作流。

## 为什么增加这个入口

原有主演示由结构化样例生成合成文本，尚不能直接通过CLI读取一组用户自己的文本单证。拼接多份原文时，票号、国家字段和重复字段也可能发生覆盖。新入口为每份单证单独抽取并保留字段行号，同时检查归票与版本歧义。

## 使用

在已安装项目的环境执行；若未安装，可先设置 `PYTHONPATH` 为仓库 `src` 目录。

```powershell
python -m yuexian check --input data/text_bundles/hold.json --output report.json
python -m yuexian check --input data/text_bundles/send.json
python -m yuexian check --input data/text_bundles/review.json
```

也支持 `--threshold 0.05`。无效阈值进入核验，不直接放行。输出包含原文，请按业务数据权限管理。

CLI退出码0表示处理成功，并不表示可以申报；业务结论须读取 `judgement.verdict`。输入JSON损坏、结构错误、超限或读写失败返回非零退出码。批处理通过 `run_batch` 接入该格式，单票语法错误回退review，其他票继续处理。

输入格式：

```json
{
  "id": "SHIP-001",
  "title": "本地文本单证核验",
  "documents": [
    {
      "name": "packing.txt",
      "station": "packing",
      "text": "票号：SHIP-001\n毛重（公斤）：12480\n"
    }
  ]
}
```

这一份单证缺少其他比较依据，结果会是待核验。完整三种状态示例均来源于仓库已有合成样例，不是真实单证或独立准确率评测集。

## 支持范围与规则

- 单证包只接受id、可选title和documents，1～10份文本；每份必须含name、station、text。name唯一，作为显示标识，不作为磁盘路径使用。
- station支持booking、packing、bl、manifest、declaration。原文没有站点时使用声明元数据；原文站点不一致时要求核验。同站点多版本不自动选择有效版本。
- 原文每份不超过200000字符；CLI文件不超过4MB，读取UTF-8及带BOM的UTF-8。
- 识别现有中英文标签字段；票号须与单证包一致，原文缺少票号须核验。重复同字段不同值、不同单证的国家字段不一致均加入pending。
- 已有规则发现冲突时仍为hold；无已有冲突但有身份/版本问题为review，不能被后写字段覆盖成send。
- evidence记录单证名、声明站点、1起始行号、原始行、原始字段值和OCR标记。精确行号对应未过滤原文，保留页眉等未识别行，不为它们生成业务字段。
- 不调用付费模型或引入新依赖。不是PDF、OCR或EDI解析器；暂未接入网页上传入口。

判定仍遵循当前有限规则。send不代表完整海关合规认证；国家冲突需人工确认而非自动解释为违法。
