# 数据流

一票货从单证文本到「先别申报」，后一段只读前一段的产物。

```text
输入（单证文本 / 结构化样例 / 未接入的文件类型）
        |
        v
接入 ingest        结构化样例渲染成装箱单、提单和已提供的历史记录
        |
        v
调度 dispatch      规则按类型选路，不由模型选择
                   text/form → 栏位抽取
                   json/shipment → 同一套对齐和判定
                   pdf、图片、证书、HS → 不解析，回退为待核验
        |
        v
预处理 preprocess  去掉页眉、水印和空行
                   滤完后没有栏位则回退到过滤前文本
                   原文就没有栏位则标记缺失，不中断
        |
        v
抽取 extract       栏位标签抽出毛重、柜号、封条、国家
        |          有 DASHSCOPE_API_KEY 时，千问另抽一版，只作对照
        v
对齐 structure     按站点排成观测序列，抽取误差单独标
        |
        v
判定 decide        毛重偏差、柜封号是否第二版、四国是否写成一格
        |
        v
解释 explain       复述判定。与判定不一致则流水线报错
```

大量文件走 `python -m yuexian batch --repeat N`。每票独立调度，线程池异步执行，返回顺序与输入一致。某一票不合规只回退这一票，不让整批失败。

回退文案集中在 `FALLBACK`：未接入类型、不合规或处理失败、缺少可抽取栏位。噪声过滤若会抹掉栏位，回退到过滤前文本，不改判定规则。

异步压舱：`python -m yuexian ballast --repeat 40`。把样例重复扩批，并夹入 PDF 这类未接入文件。压完后样例结论必须与同步判定一致，未接入文件必须计为回退。

评测集仍是 `data/shipments.json`。演示页先走单证文本，再显示判定。页脚三个数来自金标准上的规则复算。

页面逐票判定与解释统一使用抽取流水线输出。历史记录只在样例确实提供该站点字段时渲染，不能用未提供的记录猜测改写源头。出生站表示已提供记录中的首次可观察差异，不保证是真实错误发生源头。

缺少比较所需字段、毛重无效或国家字段不完整时，列出待核验项；没有已知冲突则显示「资料待核验」，已有冲突仍显示「先别申报」。模型对照不参与最终决定。

参考的做法来自单证审批类开源流水线：抽取、结构化、决定分开，低置信或看错的格子不能直接变成退单结论。本仓库没有复制那些项目的代码。

## 以后接数据库

对应代码在 `src/yuexian/store.py`，用标准库 SQLite 表达下面五张表。当前演示、规则判定和压舱都不调用它，仍读 `data/shipments.json`，也不连接外部数据库。

1. 原文、抽取字段、规则结论分三张表。结论只追加。整改复检不覆盖上一次的「先别申报」。
2. 文件本体放对象存储。库里只留类型、校验和、存储位置，以及调度规则选了哪条路径。
3. 异步用任务表。一票一行，状态是待处理、处理中、完成、已回退。失败写下回退原因，不删任务，也不让整批一起回滚。
4. 每条结论记下阈值和规则版本。以后改判定线，历史票仍按旧结论可复算。
5. 以票号为边界。一票内部的多份单证一起读。票与票之间不做大事务。
