# 本次可靠性优化

日期：2026-10-10。本地分支 `fix/validation-and-trace`，基于 `c4042a45c604582c7710d20fd000a264e043f5e1`。本次改动适合由团队审查后单独合并，与 PR #2 的运营方案修改无文件重叠。

## 已完成的修改

- 缺失字段进入「资料待核验」，不再将未完成检查当成可以申报。已有冲突仍优先「先别申报」。页面、解释和规则使用相同状态。
- 毛重统一解析正确的千位分隔符、小数及明确公斤单位。非法文本、未知单位、零、负值、布尔值和非有限数值进入人工核验，不触发数值比较异常。
- 合成单证保留实际提供的历史站点和舱单，不从样例金标准补回未抽出的国家字段。主演示票的装箱差异定位现在可由同一条抽取流程复算。
- 页面逐票结果改用流水线判定；页脚仍按既有规则复算样例统计。提供折叠的历史与舱单依据，原有主面板和离线功能继续可用。
- 改写位置文案说明为「首次可观察差异」，避免从有限记录断言真实改写源头。
- 修正 Windows 测试子进程的中文编码，避免 UTF-8 输出被按 GBK 解码。
- 交稿自检同时复算逐票判定、单证、轨迹和解释；即使页脚数字没变，页面内嵌结果过期也会失败。异常统计值和逐票数据会明确报错。
- 千问轨迹增加 `qwen_status`：关闭、无提单、未配置、失败、收到响应分别记录。收到响应仅表示接口返回非空文本，不表示 JSON 已验证或已参与判定。测试使用模拟返回，未发起收费调用。

## 验证结果

- 原有 15 项测试保留，增加回归覆盖后共 33 项通过。
- `tools/verify_submission.py` 通过。
- 与修改前快照逐项比较，原有 6 票的既有判定字段和所有页脚统计不变；增加 `pending` 字段供不完整输入使用。
- 页面 JavaScript 在模拟 DOM 中验证拦截、通过、待核验三种状态；该检查不等于浏览器截图或人工视觉验收。
- 没有新增第三方依赖或强制网络请求，未调用收费模型。

本机 6 票样例微基准，每项 5 轮、每轮 300 次，取单次平均耗时的中位数：规则统计约从 0.055 ms 到 0.044 ms，完整流水线约从 0.181 ms 到 0.333 ms。新增完整性检查和历史文本使流水线增加约 0.152 ms。这里只能说明本机小样例下开销很小，不能宣称所有负载下零性能变化或稳定加速。

补充模型状态与交稿自检后，同口径复测规则统计约 0.053 ms，完整流水线约 0.342 ms；原有 6 票的既有字段和页脚统计再次与基线快照核对一致。

## 复核与使用

```powershell
python -m unittest discover -s tests -t . -v
python tools/verify_submission.py
```

浏览器打开 `demo/index.html`。若未安装包，构建前可临时设置当前终端的 `PYTHONPATH` 为仓库 `src` 目录，再运行 `python -m yuexian.build_demo`。

新的 `review` 状态属于接口变化。若另有程序仅接受 `hold/send`，需补充 `review` 处理；仓库内的页面和解释已经适配。对直接传入规则的输入，仍约定 shipment、countries 和 observations 符合现有字典/列表结构，未增加任意 JSON 结构导入功能。

尚待后续实现：外部 PDF/图片/EDI 输入、HS 编码、目的国规则、独立真实单证评测、模型输出的实际集成，以及运营执行数据。本次可靠性改动不等同于完成上述赛题缺口。
